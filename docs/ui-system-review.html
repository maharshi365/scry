Where the shared layer leaks

01

Selected state has several visual definitions

Library tabs use a filled surface. Calendar and library type filters append “✓”. Source filters add an accent border. Add-on tabs do not get a selected treatment.

library_view/mod.rs:393–440 · calendar.rs:184–201 · source_picker.rs:36–50 · addons.rs:90–92
02

Icons and their accessible names are not shared

Refresh, close, season arrows, and play indicators are text symbols. The player already has vector icons and explicit action names. Reuse that approach; do not use the visible glyph as the control’s name.

shell.rs:188 · addons.rs:110 · detail.rs:204–218 · source_picker.rs:308 · player/mod.rs:308–424
03

Interaction rules vary with the layout code

The context menu explicitly adds focus behavior. Catalog cards have press handlers but no explicit button role or label. Shared interactive primitives should own consistent naming, focus, and disabled behavior.

context_menu.rs:85–100 · discover.rs:79–91 · components.rs:80–111

Keyboard activation and focus-ring rendering need runtime verification; this review does not claim they are broken.

04

The current components mix appearance with app commands

The input helper routes submit behavior by key string. The player’s icon button also gates playback and handles the fullscreen transaction. Extract the visual shell, but keep these policies in feature code.

components.rs:114–143 · player/mod.rs:308–331

A small module boundary, not a new UI framework

│   ├── mod.rs

├── detail.rs         # episode state + actions
└── player/           # playback policy + transactions

Dependency direction

Screens + feature state
↓ compose
Shared primitives
↓ consume
Tokens + icons → Rune

Primitives receive callbacks. They do not read navigation, playback, or services. Start inside this crate. A separate workspace crate is not needed.

Formatting helpers such as clock and excerpt do not belong in the design layer. Keep feature geometry, virtualization, and artwork loading outside it.

Suggested order

1 / CENTRALIZE WITHOUT REDESIGN

Tokens + icons

Move existing values and vectors to shared modules. Replace text-only action glyphs. Preserve the current look before unifying variants.

2 / PROVE THE API ON REAL SCREENS

Buttons + selection

Use the shell and library first. Add shared selected, disabled, and busy states. Then move the add-on, calendar, and source controls.

3 / CONSOLIDATE REPEATED PATTERNS

Text + surfaces

Extract repeated text roles and panel treatments. Share dropdown behavior only after season and provider requirements are clear.

Guardrails: Preserve element keys, scroll bounds, poster virtualization, and fullscreen transaction behavior. Extend the existing Rune runtime tests for labels, focus, disabled/busy actions, and selection. Compare native screens at 880 × 600 and 1280 × 820. Do not test Rune’s own rendering internals.

Review artifact only. No application source was changed and no tests were run. Native visual and keyboard validation remain follow-up work.
